# 会議リアルタイム翻訳（日 ⇄ 中）

[中文](README.md) ｜ [English](README.en.md) ｜ [日本語](README.ja.md)

[![CI](https://github.com/Yang-Code01/meeting-translate/actions/workflows/ci.yml/badge.svg)](https://github.com/Yang-Code01/meeting-translate/actions/workflows/ci.yml)

Windows 向けの小さなデスクトップツールで、機能は 2 つあります。

- **会議のリアルタイム翻訳** — **任意の会議アプリ**の音声を取り込み（システムのループバックを【相手】、マイクを【自分】として扱います）、音声認識をローカルで行い、GitHub Copilot または自前の OpenAI 互換端点で翻訳して、最前面のオーバーレイに日中のバイリンガル字幕を表示します。会議終了後には議事メモ・アクションアイテム・整形済みのバイリンガル全文を生成できます。
- **選択範囲の翻訳** — 任意のアプリで日本語を選択して **Alt+M** を押すと、カーソル付近に中国語訳とふりがな付きの原文が表示されます。専用の事前ウォーム済みセッションを使うため、進行中の会議翻訳を妨げません。

会議プラットフォームに依存せず（Teams / Zoom / Webex / Meet / Tencent Meeting いずれも可）、仮想オーディオケーブルも不要です。音声認識はすべて CPU 上で完結し、選択したモデルサービスへ送られるのはテキストだけです。

## 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / 11（WASAPI ループバックを使用） |
| アカウント | GitHub Copilot のサブスクリプション、または OpenAI 互換サービスの API key（翻訳と要約を担当） |
| ハードウェア | 一般的な x86-64 CPU で可。GPU 不要。認識は既定で 4 スレッド |
| マイク | 任意。有効にすると自分の発話が【自分】として記録されます。ヘッドホン推奨 |

## インストール

### 方法 1：ビルド済み exe を使う

1. [Releases](https://github.com/Yang-Code01/meeting-translate/releases/latest) から `MeetingTranslate.exe`（約 400 MB、認識モデルと Copilot ランタイムを同梱）をダウンロードします。
2. 実行します。初回起動時は同梱リソースの展開に約 15 秒かかり、準備ができるとタスクトレイに「译」アイコンが現れます。
3. 初回は Copilot へのログイン（[ログイン](#copilot-へのログイン) 参照）、または設定での自前 API key の登録が必要です。

レジストリには書き込まず、管理者権限も不要です。アンインストールは exe と `%APPDATA%\meeting-translate\` を削除するだけです。

### 方法 2：ソースから実行する

[uv](https://docs.astral.sh/uv/) と Python 3.12 以上が必要です（開発環境は 3.14）。

```powershell
uv sync
uv run python scripts/fetch_models.py   # 認識モデルを models/ に取得（約 380 MB）
uv run python main.py                   # 実行（Copilot ログイン済みであること）
```

`uv.lock` には作者環境で使用している清華大学ミラー（`pypi.tuna.tsinghua.edu.cn`）が記録されています。中国国内なら `uv sync` のままで構いません。**中国国外**では `uv.lock` を削除してから再解決するか、次のように実行してください。

```powershell
uv sync --index-url https://pypi.org/simple --refresh
```

### Copilot へのログイン

未ログインで起動すると案内が表示され、次のいずれかを選びます。

- **方法 1（推奨）** — `copilot` CLI が入っている場合、「打开控制台执行 copilot login」を押し、開いたコンソールでログインを済ませてから再検出ボタンを押します。
- **方法 2** — **Copilot Requests** 権限を付けた fine-grained Personal Access Token を貼り付けます。

### 自前のモデルサービスを使う（API key を持ち込む）

1. 設定 →「モデルサービス」で「カスタム（OpenAI 互換）」を選び、「新規…」を押します。
2. 名前・エンドポイント（例 `https://api.deepseek.com/v1`）・モデル名（例 `deepseek-chat`）・API key を入力します。単価は空欄なら金額換算しません。
3. OK で即時反映され、再起動は不要です。

- `/chat/completions` を実装していれば接続できます：DeepSeek、Kimi、Qwen、OpenAI、Ollama、vLLM、社内ゲートウェイなど。
- API key は Windows DPAPI で暗号化して `config.json` に保存します。別の PC や別の Windows ユーザーでは再入力が必要です。
- 使用量はトークン単位です：オーバーレイに会議中の入力／出力トークンを表示し、単価を入れた場合のみ金額換算します。アカウント全体の割当は取得できません。
- 会話履歴はローカルで保持し、毎回の送信に含めるため、会議が長いほどトークン消費が増えます。ローテーション間隔は設定で変更できます。
- 社内の自己署名証明書を使う端点では、その設定だけ「証明書の検証を省略」をオンにできます。公開端点では有効にしないでください。
- 会議中にサービスを切り替えると、旧バックエンドで前情要約を作ってから新バックエンドでセッションを張ります。失敗した場合は旧セッションを継続します。

## 使い方

### 会議を始める

1. **Ctrl+Alt+J**（またはトレイメニュー／オーバーレイの「▶ 开始」）で開始します。もう一度押すと一時停止、「▶ 继续」で再開します。
2. オーバーレイに日本語が流れ、文が終わったところ（VAD が無音を検出）で中国語訳が追加されます。【相手】と【自分】は別々のストリームとして扱われます。
3. 「■ 结束」で会議を終了すると、議事メモを作成するかどうかを尋ねられます。

翻訳方向（日→中／中→日）は設定で切り替えます。**会議中はロック**され、次回の開始から反映されます。中→日では中国語認識に常に SenseVoice を使い、用語集は逆方向に使われ、議事メモとアクションアイテムは日本語で書かれます。

### オーバーレイとトレイ

- オーバーレイは最前面・半透明で、ドラッグで移動、四隅のドラッグでサイズ変更、ウィンドウ端のダブルクリックで全画面と元のサイズを切り替えます。文字サイズと不透明度は設定で変更します。
- 「—」で非表示、トレイの「显示/隐藏字幕窗」で再表示します。設定で「字幕ウィンドウを表示」をオフにすると、起動時はトレイアイコンとホットキーだけになります。
- 設定で「字幕モード」を有効にすると、原文や未完成の断片を表示せず訳文だけを表示します。動画の字幕として使えます。
- 「🎤 麦克风」ボタンで自分のマイクの使用を切り替えます。状態は記憶され、会議中でも即時反映されます。
- トレイメニュー：開始／一時停止、会議終了、字幕ウィンドウの表示切替、設定、モデル（クイック切替）、用語集の編集、記録フォルダを開く、過去会議の整理、Copilot ログイン、終了。
- 設定ウィンドウはモードレスで、開いたままオーバーレイを操作できます。項目を変更すると OK の左に「设置已修改，点击 OK 后生效」と表示され、OK を押さずに閉じると変更は破棄されます。オーバーレイが表示されているときは、設定ウィンドウは広い側に開きます。

### 選択範囲の翻訳（Alt+M）

**任意のアプリ**で日本語を選択し **Alt+M**（変更可）を押すと、カーソル付近に小さなポップアップが出て、中国語訳とふりがな付きの原文を表示します。

```
会議の資料を送ります
会議（かいぎ）の資料（しりょう）を送（おく）ります
```

- 中国語訳・かな・漢字の 3 行はそれぞれ文字サイズと色を変更でき、漢字行は非表示にできます。
- ポップアップはサイズ変更でき、次回も記憶されます。
- 専用の事前ウォーム済みセッションを使うため、会議中の翻訳経路を妨げません。
- 履歴はメモリ上に溜まり、設定の「保存划词/句翻译历史」を押したときに `selection_translation_history.md` へ書き出されます（重複は自動除去）。

> 仕組み：ホットキー押下時に Ctrl+C を送出して選択範囲を読み取り、元のクリップボード内容を復元します。したがって**先にテキストを選択してから**ホットキーを押してください。

### 文の分割とフィラー

- **分割** — 0.6 秒の無音で 1 区切り。て／が／けど／ので などで終わる場合や 1〜3 文字だけの場合は「言い終わっていない」とみなして後続を待ちます（中国語は 的／和／但是／因为 など）。待ち時間は最大 3 秒、結合後 20 秒を超えたら送信、1 文が 10 秒を超えたら強制分割します。いずれも設定で変更できます。
- **フィラー** — え／あ／えー／えーと／あの／うん／ん などが単独で発話された場合は原文のみ表示し、翻訳しません。中国語のリストは別に管理します。どちらも設定で編集できます。
- **エコー除去** — マイクを有効にしてヘッドホンを使わないと、相手の声もマイクに入ります。4 秒以内に【相手】の発話と類似度 0.75 以上だった【自分】の文は破棄しますが、これはあくまで保険です。ヘッドホンを使用してください。

### 用語集

トレイメニュー「编辑术语表」で 1 行 1 項目：

```
取引種別            # 訳語を書かなければ原文のまま
リリース = 发布      # 訳語を指定
```

用語は翻訳プロンプトと音声認識のホットワードの両方に使われます。変更は次回の開始から反映されます。

> ホットワードが効くのは **ReazonSpeech** のみです。既定の SenseVoice はホットワード非対応ですが、用語集は翻訳側で効きます。

### モデルと使用量

- 設定には利用可能なモデルが推定コストの安い順に並び、1 時間あたりの推定 AIC、基準モデルの何倍か、平均遅延が表示されます。「测速」で選択中のモデルを実測できます。
- 会議中のモデル切替は即時反映されます。旧モデルで前情を要約し、その要約＋直近 5 文＋用語集を新セッションに渡し、ウォームアップ後に切り替えます。
- 選択した推論強度にモデルが対応していない場合は自動的に下げ、ステータスバーに表示します。
- オーバーレイは既定で「アカウント使用済み AIC」「今回の AIC」を表示します。「アカウント残量 %」は既定で非表示ですが、10% を下回ると設定に関係なく赤く表示されます（会議は中断しません）。
- カスタム端点を使う場合、オーバーレイと会議記録は今回の入力／出力トークンを表示します。単価を入れたときだけ金額換算し、アカウント割当の行は表示されません。
- 1 会議につき 1 セッション、30 分ごとにローテーション（変更可）。各リクエストはセッション履歴を伴うため、これが主な消費要因です。

### 会議後の整理

会議終了時に「議事メモ・アクションアイテム・整形済みバイリンガル全文を作成しますか？」と尋ねられます。

- 作成中はオーバーレイに段階的な進捗が表示され、完了すると整理稿が自動的に開き、トレイ通知が出ます。失敗時は「重试」で再試行できます。
- 整理稿のファイル名：`<AI が付けたタイトル>_<生成日時>.md`（例：`订单缺陷复盘_2026-10-14_140530.md`）。
- バイリンガル記録は `<会議開始時刻>.md` で、同じフォルダに保存されます。
- トレイの「整理历史会议…」で、既存のバイリンガル記録を対象に再整理できます（整理稿は無効な入力として拒否されます）。

### 設定の反映タイミング

| 即時反映 | 次回の開始から反映 |
|---|---|
| 翻訳モデル、推論強度、マイクのオン／オフ、モデルサービスと端点 | 音声デバイス、翻訳方向、認識エンジン、認識補正、分割の 3 項目、セッションのローテーション間隔 |

## データの保存場所

すべて `%APPDATA%\meeting-translate\` にあり、どこにも送信されません。

| ファイル | 内容 |
|---|---|
| `config.json` | 設定（カスタム端点の API key は Windows DPAPI で暗号化して保存） |
| `model_stats.json` | モデルごとの実測遅延と過去の使用量（コスト推定用） |
| `glossary.txt` | 用語集 |
| `selection_translation_history.md` | 選択範囲翻訳の履歴（保存操作をしたときのみ書き込み） |
| `transcripts\` | 会議中の一時記録。保存先未設定時の既定の場所 |
| `models\` | 任意ダウンロードの認識モデル（exe 版では不要） |
| `app.log` | ログ |

会議終了後は Markdown のみ残ります。バイリンガル記録 `<会議開始時刻>.md` と整理稿 `<タイトル>_<日時>.md` が設定した保存先に書き出されます（初回の終了時に一度尋ね、キャンセルした場合は今回のみ既定の場所に保存し、次回また尋ねます）。一時 `.json` は整理の完了または中止後に削除され、失敗時は再試行できるよう保持されます。

## プライバシーと利用上の注意

- **録音には同意が必要です。** 法規制は地域によって異なります。会議音声を取得する前に、参加者から同意を得てください。
- 認識された**テキスト**は、設定で選択したモデルサービスへ送信されます：既定は GitHub Copilot（GitHub / Microsoft）、または自分で設定した OpenAI 互換端点です。音声そのものは端末外に出ません。本ツールはテレメトリを収集せず、作者にデータを送信しません。
- 第三者端点を使う場合、会議テキストはその提供元に渡ります。保存期間や学習利用の可否は提供元の判断です。同梱テンプレートには主なサービスの方針を記載していますが、機密会議ではご自身で確認してください。
- ログ・記録・用語集はすべて端末の `%APPDATA%` 配下に留まります。
- マイクは話者を区別できません。近くにいる人の発話も【自分】として記録されます。問題になる場面ではマイクをオフにしてください。
- 本アプリはシステムのオーディオ設定を変更せず、ドライバもインストールしません。

## 既知の制限

- Windows のみ：音声取得が WASAPI ループバックに依存しており、クロスプラットフォーム化の予定はありません。
- 既定の Copilot 経路はサブスクリプションが必要で、AIC とリクエスト数で課金されます。カスタム端点ではトークン課金になり、割当は提供元が決めます。
- 既定の SenseVoice はホットワード非対応です。必要なら ReazonSpeech（やや低速）に切り替えてください。
- 話者の区別は【相手】／【自分】の 2 系統までで、同じ部屋の複数話者は分離できません。
- exe は約 400 MB で、起動時に展開が必要です（初回は約 15 秒）。
- 一時停止は現在の文を強制的に確定するため、文中で停止すると文が途切れることがあります。

## 技術的なポイント

- **認識の前に分割する** — 音声全体を sherpa-onnx に渡すと最後の 1 文しか出力されないため、silero VAD で先に分割し（既定は無音 0.6 秒、1 区切り最大 10 秒）、区切りごとにデコードします。4 スレッド CPU で日本語 1 文あたり約 0.35 秒です。
- **言い終わっていない文を結合する** — 無音だけの分割では「〜ですが／〜ので」が寸断されるため、日本語の文末判定＋3 秒の待ち＋20 秒の結合上限を重ね、結合後を 1 文として翻訳・表示します。
- **1 リクエストで 2 つの処理** — 翻訳時に同じ応答内で認識誤りの補正と翻訳を行い、リクエスト回数を増やしません。補正後の原文が表示と記録の両方に使われます。
- **コストの可視化** — 各モデルの実測遅延と AIC 単価から「1 時間あたりの推定 AIC」を算出して設定に表示し、その場で実測もできます。
- **選択範囲翻訳は独立セッション** — 会議中の翻訳経路に影響せず、事前ウォームアップによりホットキーですぐ結果が出ます。

```powershell
uv sync
uv run python scripts/fetch_models.py   # ReazonSpeech + SenseVoice + silero VAD を models/ に取得

```
